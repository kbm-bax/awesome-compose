## WordPress with MySQL
This example defines one of the basic setups for WordPress. More details on how this works can be found on the official [WordPress image page](https://hub.docker.com/_/wordpress).


Project structure:
```
.
├── compose.yaml
└── README.md
```

[_compose.yaml_](compose.yaml)
```
services:
  db:
    # We use a mariadb image which supports both amd64 & arm64 architecture
    image: mariadb:10.6.4-focal
    # If you really want to use MySQL, uncomment the following line
    #image: mysql:8.0.27
    ...
  wordpress:
    image: wordpress:latest
    depends_on:
      wordpress-setup:
        condition: service_completed_successfully
    ports:
      - 80:80
    restart: always
    ...
  wordpress-setup:
    image: wordpress:cli
    ...
  wordpress-files:
    image: wordpress:latest
    ...
```

When deploying this setup, docker compose maps the WordPress container port 80 to
port 80 of the host as specified in the compose file.

The WordPress container is only started after the one-shot `wordpress-setup`
service has installed WordPress with WP-CLI (`wp core install`) and created the
administrator account. The web installation wizard is therefore never reachable,
so nobody who can reach port 80 can claim the site before you do.
`wordpress-files` copies WordPress into the shared `wp_data` volume and writes
`wp-config.php` before the installer runs.

The installer can be configured with these variables (in the shell or an `.env` file):
`WORDPRESS_URL` (default `http://localhost`), `WORDPRESS_TITLE`,
`WORDPRESS_ADMIN_USER` (default `admin`) and `WORDPRESS_ADMIN_EMAIL`.
The administrator password is randomly generated by WP-CLI.

> ℹ️ **_INFO_**  
> For compatibility purpose between `AMD64` and `ARM64` architecture, we use a MariaDB as database instead of MySQL.  
> You still can use the MySQL image by uncommenting the following line in the Compose file   
> `#image: mysql:8.0.27`

## Deploy with docker compose

```
$ docker compose up -d
Creating network "wordpress-mysql_default" with the default driver
Creating volume "wordpress-mysql_db_data" with default driver
...
Creating wordpress-mysql_db_1        ... done
Creating wordpress-mysql_wordpress_1 ... done
```


## Expected result

Check containers are running and the port mapping:
```
$ docker ps
CONTAINER ID        IMAGE               COMMAND                  CREATED             STATUS              PORTS                 NAMES
5fbb4181a069        wordpress:latest    "docker-entrypoint.s…"   35 seconds ago      Up 34 seconds       0.0.0.0:80->80/tcp    wordpress-mysql_wordpress_1
e0884a8d444d        mysql:8.0.19        "docker-entrypoint.s…"   35 seconds ago      Up 34 seconds       3306/tcp, 33060/tcp   wordpress-mysql_db_1
```

The `wordpress-setup` and `wordpress-files` containers exit after they finish.
Read the generated administrator password from the installer's output (it is
only printed on the first start):
```
$ docker compose logs wordpress-setup
...
Admin password: <generated password>
Success: WordPress installed successfully.
```

Navigate to `http://localhost:80` in your web browser to access WordPress, and log in
at `http://localhost/wp-admin/` with that user. Change the password after your first login.

![page](output.jpg)

Stop and remove the containers

```
$ docker compose down
```

To remove all WordPress data, delete the named volumes by passing the `-v` parameter:
```
$ docker compose down -v
```
